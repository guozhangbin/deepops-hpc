摘要Abstract

Abstract — Verification & value assessment of the UltraLAB heterogeneous GPU cluster.

UltraLAB HPC Cluster 是一套以 Ansible 声明式交付的异构 GPU 集群：由 1 个控制/门户/监控节点（Intel Xeon Gold 5218 / 30 GB / GTX 1050）与 2 个 GPU 计算节点（i7-6700T / GTX 750、i5-9600K / GTX 1050）组成，统一由 Slurm 26.05.3 调度，通过 Open OnDemand 4.2 Web 门户提交交互式与批处理作业，并以 Prometheus 3.13.0 + DCGM + Grafana 13.1.0 实现全栈可观测。

本报告基于真实运行环境逐项实测完成：(1) 核查了 6 个 Lmod 软件模块、33 个门户应用与 49 个监控插件；(2) 实测 Slurm GPU+CPU 混合作业，验证 TRES 资源（cpu=4 + gres/gpu=1）同时分配、CPU 亲和性、GPU 可见性与 CUDA 内核执行全链路成功；(3) 梳理了"驱动 → CUDA/HPC SDK → Enroot/Pyxis → Slurm → OOD → 监控"的模块交互链路；(4) 重点介绍了 OOD-Web 的图形化提交能力；(5) 给出专业模式下的销售优势评分与结论。

关键词：异构 GPU 集群 · Slurm 调度 · TRES 混合资源 · Open OnDemand · CUDA 12.8 · Enroot/Pyxis 容器 · Prometheus/DCGM/Grafana 可观测 · 声明式 Ansible 交付

3.1 关键交互契约

  • 驱动 ↔ CUDA：驱动 580.178.04 提供内核接口，CUDA 12.8.2 在其上运行；按 GPU 代际选择 open/proprietary 内核模块（本集群 Turing 及更新用 open）。
  • CUDA ↔ 容器：Enroot 打包应用镜像，Pyxis 将 Slurm 分配的 gres/gpu 透传为容器内 CUDA_VISIBLE_DEVICES，实现"作业级 GPU 隔离"。
  • Slurm ↔ OOD：OOD 的 Batch Connect 应用把"节点/分区/核数/GPU 数/时长"等表单字段翻译为 sbatch/srun 参数；门户不直接接触 GPU，全部经由 Slurm 授权。
  • Slurm/GPU ↔ 监控：Slurm exporter（:8080）、node exporter（:9100）、DCGM exporter（:9400）三类指标统一汇入 Prometheus，Grafana 按 $hostname 聚合，避免硬编码节点名。

3.2 一次 GPU 作业的生命周期

  1. 用户在 OOD Web 门户填写作业参数（分区 / 核数 / GPU 数 / 时长 / 脚本）并提交；
  2. OOD 生成 sbatch 请求，Slurm 按 TRES 在 batch 分区匹配节点并分配 gres/gpu；
  3. slurmd 启动作业，Pyxis/Enroot 准备 GPU 容器环境，CUDA_VISIBLE_DEVICES 指向分配到的卡；
  4. 作业内 nvidia-smi 可见 GPU、nvcc 编译、CUDA 内核执行；
  5. DCGM 实时采集该卡利用率 / 显存 / 温度 / 功耗，Prometheus 存储，Grafana 呈现；
  6. 作业结束（ExitCode 0），资源回收，节点回到 IDLE。

结论　Slurm 的 TRES 机制实现了 CPU + GPU 混合资源的原子化分配——一次调度同时锁定 4 个 CPU 核与 1 张 GPU，且请求与分配完全一致、作业内两种资源均可见、CUDA 计算链路贯通。这是"异构计算"区别于"纯 CPU 集群"的核心卖点，已实测验证。
最小可复现命令　sbatch --partition=batch --cpus-per-task=4 --gpus=1 --time=00:02:00 my_job.sh　作业内用 nvidia-smi / nvcc 即可验证 GPU+CPU 双资源。

05OOD-Web 提交介绍（重点）

Open OnDemand Web submission — 把命令行 HPC 变成浏览器表单

这是面向非命令行用户（科研团队、教学、工程客户）最重要的价值点：Open OnDemand 把复杂的 Slurm 命令行封装成图形化 Web 表单，用户无需学习 sbatch 语法即可提交 GPU 作业、启动交互式软件。

5.1 三类 Web 提交入口

🖥️
Batch Connect 交互式
一键启动 Jupyter、MATLAB、ANSYS、ParaView、PyMOL 等 33 应用；表单选择节点/核数/GPU/时长，浏览器直达运行中的实例。
📜
批处理作业提交
粘贴脚本 + 填参数（分区/核数/GPU/时长/队列），后台 sbatch 执行，门户实时显示 RUNNING / COMPLETED 状态。
📊
作业与状态监控
activejobs / myjobs / projects 三应用查看队列、历史与项目配额；system-status 显示集群节点健康。

5.2 典型 GPU 作业 Web 提交流程

  1. 浏览器打开门户 http://192.168.0.200/pun/sys/dashboard/，用账户登录（已中文化界面）；
  2. 进入"作业"或目标应用（如 Jupyter / 自定义批处理），在表单中选择 分区=batch、CPU 核数、GPU 数量、运行时长；
  3. 粘贴/编辑作业脚本（或选择镜像），点击"提交"；
  4. 门户调用 Slurm 完成 TRES 混合分配（见 §04 实测），作业进入队列并调度到 GPU 节点；
  5. 在"activejobs"实时查看状态；交互式应用提交后浏览器自动打开运行中的实例；
  6. Grafana 仪表盘同步显示该 GPU 的利用率 / 显存 / 温度，实现"提交—运行—观测"闭环。

Quick start · 命令行

enroot create app.sif;  srun --gpus=1 enroot start app.sif bash
